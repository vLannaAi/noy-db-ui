# SUAI bridge map (SP-3 draft)

> **Status:** draft, 2026-07-16 — noy-db-ui drafts, suai reviews (see the cross-repo sync map).
> Final names land when the `--su-` token contract freezes (suai-css#1 / SP-1).

When the rebuilt `ui-nuxt` (on [Nuxt UI](https://ui.nuxt.com), v4 line: Reka UI + Tailwind v4)
hosts SUAI components, those components read only `--su-*` variables. This bridge derives them
from Nuxt UI's theme variables so SUAI components **blend into the host look automatically** —
including dark mode, with zero per-mode wiring (see "Mode handling").

Verified against the current Nuxt UI docs (v4): semantic accents `--ui-primary/secondary/
success/info/warning/error` (light `*-500` → dark `*-400`), text ramp `--ui-text-dimmed/muted/
toned/text/highlighted/inverted`, backgrounds `--ui-bg/-muted/-elevated/-accented/-inverted`,
borders `--ui-border/-muted/-accented/-inverted`, `--ui-radius`, dark via `.dark` class.

## The mapping

Load **after** `@suai/tokens` so it overrides the contract defaults:

```css
/* suai-bridge.css — Nuxt UI host → SUAI tokens */
:root {
  /* surfaces */
  --su-bg: var(--ui-bg);
  --su-bg-accent: var(--ui-bg-elevated);

  /* text ramp — 1:1 with Nuxt UI's */
  --su-fg: var(--ui-text-highlighted);
  --su-muted: var(--ui-text-muted);
  --su-subtle: var(--ui-text-dimmed);

  /* borders */
  --su-border: var(--ui-border);
  --su-border-subtle: var(--ui-border-muted);

  /* accents — chrome follows primary; data accent follows secondary */
  --su-accent: var(--ui-primary);
  --su-accent-fg: var(--ui-text-inverted);
  --su-accent-2: var(--ui-secondary);

  /* status hues (tint backgrounds auto-derive via the contract's color-mix) */
  --su-danger: var(--ui-error);
  --su-success: var(--ui-success);
  --su-warning: var(--ui-warning);
  --su-info: var(--ui-info);
}
```

## Mode handling — the key property

**Map once; dark mode flows through.** The right-hand `--ui-*` values already flip under
Nuxt UI's `.dark` class, so the bridge needs no dark block at all.

One rule follows: **in a Nuxt UI host, dark mode is driven by `.dark` only — never set
`data-su-mode`.** Setting it would activate the SUAI contract's own dark literals, which
override the bridge and fight the host (SUAI theme attributes are for SUAI-themed apps like
`ui-suai`, not for bridged hosts).

## Not mapped (deliberate)

| Token group | Why |
|---|---|
| `--su-font-*`, `--su-display-*` | No Nuxt UI variable equivalent; SUAI defaults inherit the page look closely enough. A host MAY set `--su-font-body` to its Tailwind `font-sans`. |
| `--su-shadow-*` | Keep SUAI defaults; shadows are subtle enough not to clash. |
| `--su-*-fg` status text | Contract defaults are mode-tuned already; revisit if a host reports contrast issues. |
| `--su-radius*` | ✅ verified against installed @nuxt/ui 4.10: `xs=×0.5, md=×1.5, lg=×2, xl=×3` of `--ui-radius`. Mapping: `--su-radius-control: calc(var(--ui-radius) * 1.5)` (md — Nuxt UI's control rounding) and `--su-radius: calc(var(--ui-radius) * 2)` (lg — cards/panels). |
